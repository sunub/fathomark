# 컴포넌트 매핑

`src/components/ui`의 각 컴포넌트가 플러그인 안에서 무엇이 되는지. **Components** 아래의
스토리들은 각각을 추상적인 형태가 아니라 코필럿에서 쓰이는 형태로 보여줍니다.

| 컴포넌트 | 코필럿에서의 역할 | 쓰는 variant |
|---|---|---|
| `bubble` | 질문은 오른쪽 정렬. **답변은 `ghost`** — 400px에서 산문을 말풍선에 넣으면 줄당 글자수가 무너집니다. | `tinted`(사용자), `ghost`(어시스턴트) |
| `marker` | 툴 호출 하나에 한 줄, 그리고 런 구분자. 툴 활동이 산문으로 섞여 들어가지 않게 하는 장치입니다. | `default`, `separator` |
| `attachment` | 컨텍스트 칩, 출처 카드, 메모리 행. `state`가 idle → loading → error를 이미 다룹니다. | `sm`, `horizontal` |
| `alert` | 지속되는 실패와 출처 충돌. 액션 행을 포함하고, 사라지는 토스트는 쓰지 않습니다. | `destructive`, 그리고 pending 틴트 |
| `badge` | 런 상태, `LOCAL`, 인용 번호. 패널에 남은 유일한 대문자입니다. | `outline`, 증거 색별 틴트 |
| `message-scroller` | 대화 영역: 스트리밍 중에는 바닥에 붙고, 독자가 위로 스크롤하는 순간 놓아줍니다. | viewport + 점프 버튼 |
| `table` | 답변 안에서만, 패널 전체 폭으로. 그 외에는 목록이 됩니다. | compact |
| `spinner` | 이름이 붙은 활동 옆에서만 씁니다("Reading Wikipedia page…"). 혼자 도는 일은 없습니다. | — |
| `button` | Stop과 Apply가 제품 전체에서 유일한 전폭 버튼입니다. | `default`, `outline`, `ghost` |

## 아직 라이브러리에 없는 것

패널의 세 부분은 아직 화면마다 손으로 그리고 있습니다. 다음에 분리할 컴포넌트이고,
순서는 이렇습니다.

1. **Composer** — 입력 필드, 핀과 범위 칩, 전송/정지 슬롯. 네 화면에 등장하고, 전송
   슬롯이 런 상태에 따라 바뀌기 때문에 가장 어긋나기 쉽습니다.
2. **BudgetBar** — 모노 `used / total`, 구간 막대, 리저브 라벨. 지금 세 화면이 그리고
   있고, 이미 한 번 어디에 두는지를 두고 서로 어긋났습니다.
3. **DiffView** — 삽입 미리보기의 줄 diff. 한 화면뿐이지만 Vault에 쓰는 바로 그
   화면이라, 마크업이 아니라 테스트된 컴포넌트가 될 자격이 있습니다.

<Rule kind="dont" title="화면에 박스가 필요하다는 이유로 컴포넌트를 만드는 것">
  위 세 개는 이미 두세 번 중복되어 있어서 자격을 얻었습니다. 한 번만 나타나는 모양은
  마크업입니다. 첫 번째가 아니라 두 번째 복사본에서 분리하세요.
</Rule>

## 플러그인 밖에서 쓰기

여기 있는 것은 전부 아래로 내려가면 평범한 shadcn/base-ui이고, Fathomark의 인상은
컴포넌트가 아니라 토큰 레이어에서 나옵니다. `theme-fathomark` 클래스를 떼면 같은
컴포넌트가 기본 라이트/다크 팔레트로 렌더됩니다. 툴바의 **Theme** 컨트롤이 그 사이를
전환하는데, 색을 하드코딩한 컴포넌트를 찾아내는 가장 빠른 방법이기도 합니다.
