# 커리어 글쓰기 UI 디자인 브리프

Claude Design에 전달하는 문서. 기존 Fathomark Chat UI([`chat-ui.md`](./chat-ui.md))에 **새로 들어오는 화면과 컴포넌트**를 디자인해 달라는 요청이다. 작성일 2026-10-05. 기준 계획: `docs/superpowers/plans/2026-10-05-career-writing-index.md`.

## 1. 제품 맥락 (한 문단)

Fathomark는 Obsidian 오른쪽 사이드바(기준 폭 400px, 320–520px에서 유지)에서 동작하는 에이전트다. 첫 번째 용도는 **커리어 글쓰기**: 사용자가 채용 공고나 지원 질문을 붙이면, 자기 Vault 노트에서 경험을 찾아 근거로 인용하며 이력서 bullet과 자기소개서 답변 초안을 쓴다. 노트에 없는 경험은 지어내지 않고 "근거 없음"으로 표시한다. Vault에 쓰는 것은 사용자가 미리보기에서 승인한 뒤에만 한다.

- 💡 **주장(claim)**: 초안 안에서 사실로 서술된 한 문장 단위입니다(예: "API 응답 시간을 800ms에서 320ms로 줄였다"). 각 주장은 근거 노트에 연결되거나 "근거 없음"이 됩니다.
- 💡 **근거(evidence)**: 주장을 뒷받침하는 Vault 노트의 발췌(경로, 제목, 본문 구간)입니다.

## 2. 지켜야 할 기존 규칙 (전부 유효, 요약)

원문은 `chat-ui.md`. 새 디자인이 아래를 어기면 안 된다.

1. 패널 안에 **구분선 없음**(헤더 아래, 컴포저 위, 섹션 사이). 섹션은 여백으로 나눈다.
2. 테두리는 "사용자가 조작하는 것"(카드, 칩, 컴포저)에만. 레이아웃 컨테이너에는 없음.
3. 패널 안에 **제품명·로고 없음**. 단일 요소 위의 대문자 라벨 없음. 대문자는 상태 배지 전용(`STREAMING`, `COMPLETE`, `FAILED`, `NOT APPLIED`, `LOCAL`).
4. **컴포저는 항상 존재**한다. 종료 상태도 입력을 막지 않는다. 주 화면 하단 순서는 상태별 행 → 예산 바 → 컴포저 → 모델 상태 줄.
5. **색은 의미만 나른다**: `--fm-brand`(에이전트), `--fm-vault`(내 노트에서 온 증거), `--fm-external`(네트워크에서 온 것), `--fm-pending`(미검증/사용자를 기다림), `--fm-error`(실패), `--fm-ok`(모델에 닿음). 브랜드 보라는 증거 위에 얹지 않는다. 채움 위 글자는 `--fm-*-ink`(흰색 아님).
6. 서체 두 목소리: 산문은 Public Sans 13px, 기계적인 값(경로, 토큰 수, 시간, 바이트)은 IBM Plex Mono 11.5px.
7. **하위 화면**(뒤로가기 + 이름 + 상태 배지 + 하단의 단일 주요 동작, 컴포저 없음)은 의도적으로 주 화면과 다르다.
8. 채워진 브랜드 버튼은 제품 전체에서 **전송, Apply to note** 두 곳뿐이다. (아래 4번 화면에서 이 규칙과 충돌할 수 있어 질문으로 남겼다.)
9. 아이콘만 있는 버튼은 `aria-label`, 모든 인터랙션은 실제 `button`/`a`/`input`.
10. 한국어 UI. 문장형, 간결하게. 사용 컴포넌트는 `design-system/src/components/ui`(`bubble`, `marker`, `attachment`, `alert`, `badge`, `message-scroller`, `table`, `spinner`, `button`)를 먼저 쓰고, 새 컴포넌트는 꼭 필요할 때만 만든다.

## 3. 요청: 새로 필요한 화면과 컴포넌트

우선순위 순. 각 항목에 상태(정상, 비어 있음, 오류, 로딩)와 라이트/다크(`theme-fathomark`)를 모두 그려 달라.

### 3.1 워크플로 진행 표시 (우선순위 높음)

**무엇**: 고정 6단계 — 분석 → 검색 → 근거 선택 → 초안 → 검증 → 미리보기. 스트리밍 화면(2번)의 본문 안에서 단계가 진행되는 것을 보여 준다.

**제약**: 헤더에는 추가 요소를 넣지 않는다(기존 규칙). 가로 스테퍼나 진행 막대 같은 크롬을 새로 만들지 말고, 기존 `marker`(툴 활동 한 줄, 구분자)를 쓰는 방향을 우선 검토해 달라. 현재 단계는 이름 + `spinner`, 끝난 단계는 한 줄 요약(예: "근거 노트 4개 선택"), 실패한 단계는 `--fm-error`.

**상태**: 진행 중, 사용자 승인 대기(`awaiting approval`, `--fm-pending`), 완료, 실패, 취소.

### 3.2 근거 선택 카드 (우선순위 높음)

**무엇**: 3번 단계 "근거 선택" 결과. 모델이 고른 근거 노트 목록. 각 항목은 노트 제목, 경로(모노), 발췌 2~3줄. 사용자가 항목을 **제외/다시 포함**할 수 있어야 한다(초안 생성 전 확인용). 근거는 `--fm-vault` 색.

**구현 힌트**: `attachment`(`sm`/`horizontal`)를 쓰고, 제외 상태는 흐리게 + 토글 버튼. 400px에서 발췌가 잘리는 방식을 정해 달라.

**비어 있음 — "근거 없음" 상태**: 검색 결과 근거가 충분하지 않으면 초안을 쓰지 않는다. 문구 예: "Vault에서 이 질문에 맞는 경험 노트를 찾지 못했습니다." 아래에 가능한 행동(질문 바꾸기, 노트 추가 후 재시도). `alert`의 `warning`(`--fm-pending`) 계열. 오류가 아니므로 `--fm-error`를 쓰지 않는다.

### 3.3 주장 단위 초안 표시 (우선순위 높음, 가장 중요)

**무엇**: 초안(이력서 bullet 또는 에세이 문단)에서 각 주장 옆에 근거 상태를 표시한다. 확신보다 증거라는 원칙의 핵심 화면이다(`chat-ui.md` 7절).

| 상태 | 표시 | 색 |
|---|---|---|
| `supported` | 인용 칩 `[1]` 형태 + 근거 노트 연결 | `--fm-vault` |
| `unsupported` | "출처 없음" 표시 | `--fm-pending` |
| `invalid_citation` | "인용을 확인할 수 없음" | `--fm-pending` |
| `literal_mismatch` | 숫자·고유값이 근거와 다름. 문제가 되는 값을 강조하고 근거의 값을 함께 보여 줌 | `--fm-error` 계열 검토(실패가 아니라 검증 실패이므로 pending과 error 중 어느 쪽이 맞는지 제안해 달라) |
| `style_copy` | 사용자의 문체 예시를 그대로 베낀 구절 경고 | `--fm-pending` |

**요구사항**
- 인용 칩을 누르면 근거 발췌가 펼쳐지거나 노트로 이동한다(어느 쪽인지 제안).
- 초안 위에 요약 한 줄: 예) "주장 12개 · 근거 없음 2 · 값 불일치 1". 모노 숫자.
- 근거 없는 주장이 있어도 초안을 숨기지 않는다. 사용자가 그 문장을 지우거나 근거를 연결하거나 그대로 둘 수 있어야 한다(액션 설계 필요). 근거 없는 주장은 승인 시 노트에 "사실처럼" 들어가지 않도록 시각적으로 분명해야 한다.
- 이력서 bullet(짧은 항목 목록)과 에세이(긴 문단) 두 형태 모두 그려 달라.

### 3.4 외부 전송 동의 (하위 화면, 우선순위 높음)

**무엇**: Vault 내용이 외부(ChatGPT 로그인 provider)로 나가기 전에 **정확히 무엇이 전송되는지** 보여 주고 동의받는 화면. 로컬 provider(Gemma 4)는 이 화면이 나오지 않는다.

**구성**
- 목적지 배지: `CHATGPT`(네트워크로 나감을 뜻하므로 `--fm-external` 계열). 한 줄 설명: "아래 내용이 OpenAI 서버로 전송됩니다."
- 전송 항목 목록: 종류(노트 발췌 / 문체 예시 / 질문), 경로(모노), 바이트(모노), 미리보기 한 줄. 총합 바이트. 항목이 많을 때의 접힘 방식.
- 선택지 셋: **이번 한 번**, **이 세션 동안**, **거부**. "항상 허용"은 만들지 않는다.
- 거부하면 입력이 잠기지 않고 본 화면으로 돌아온다.

**규칙 충돌(질문)**: 하위 화면은 "하단의 단일 주요 동작"을 갖고, 채워진 브랜드 버튼은 두 곳뿐이다. 여기서 허용 버튼을 어떻게 그릴지 제안해 달라. 기본 안은 `outline` 허용 + `ghost` 거부(규칙 유지)이고, 규칙을 고쳐야 한다고 판단하면 근거와 함께 제안해 달라(제품 소유자가 결정).

### 3.5 provider 선택·상태 (우선순위 중간)

**모델 상태 줄 확장** (주 화면 하단, 4번째 줄): 현재는 점 + `모델 · 엔드포인트` + `LOCAL`. 새로 `CHATGPT`/`LOCAL` provider 배지와 모델명을 표시한다. 어떤 provider가 쓰였는지는 항상 보여야 한다.

**설정 하위 화면 — 모델**
- provider 선택: ChatGPT 로그인 / 로컬.
- ChatGPT: 로그인 상태(로그인됨, 로그아웃, 만료), `로그인`/`로그아웃` 버튼. 로그인은 시스템 브라우저가 열리고 앱이 기다리는 상태(로딩, 취소 가능)가 있다.
- 로컬(Gemma 4): 설치된 변형 목록, 기기 메모리에 맞는 권장 안내(8 GB: E2B, 16 GB: 12B 또는 E4B, 24 GB 이상: 26B-A4B), 설치되지 않았을 때의 안내 상태.

**한도 도달 알림** (`alert`, `--fm-pending`): ChatGPT 요금제의 사용 한도에 도달했을 때. 자동 전환하지 않고 사용자에게 두 선택지를 준다. 문구 예: "ChatGPT 사용 한도에 도달했습니다." / 행동: **로컬 모델로 이어서 실행**, **나중에 다시 시도**. 로컬로 바꾸면 품질이 달라지고 데이터가 기기 밖으로 나가지 않는다는 것을 한 줄로 알린다.

**provider 없음 상태**: 로그인도 안 되고 로컬 모델도 없을 때. 실패 카드 + 설치/로그인 안내. 컴포저는 살아 있다.

### 3.6 문체 예시 관리 (우선순위 중간)

현재 `StylePicker`는 선택/해제/저장 버튼 세 개뿐이다. 이를 **장르별 예시 목록**으로 확장한다.

- 장르 두 개: 이력서 bullet / 에세이. 장르 전환 방식 제안(탭이 구분선 규칙과 충돌하지 않게).
- 예시 항목: 본문 앞부분 2줄, 바이트(모노), 제거 버튼. 예시당 4,096바이트 상한이므로 넘으면 오류 상태.
- 추가 방법: 에디터에서 텍스트를 선택한 뒤 "예시로 추가". 이 동작이 어디(하위 화면 또는 컨텍스트 요약 영역)에 놓이는 게 맞는지 제안해 달라.
- 사용자가 선택한 글만 쓴다는 점을 UI가 흐리지 않게 한다(Vault를 자동으로 훑는다는 인상을 주면 안 됨).

### 3.7 승인 대기와 재개 (기존 4번 화면 보강)

기존 삽입 미리보기(diff, Apply)를 유지하면서 추가한다.
- 근거 없는 주장이 남아 있는 상태로 Apply하려 할 때의 확인. 막지는 않되 눈에 띄게. 동의 화면(3.4)과 충돌하지 않는 방식으로.
- 앱을 다시 시작하면 승인 대기 중이던 실행은 폐기된다. 이를 알리는 한 줄 알림(이전 실행을 이어갈 수 없음).

## 4. 요청하는 산출물

1. 위 3.1~3.7 화면의 **400px 기준 목업**과 320/520px 변형 확인(핵심 화면만). 라이트/다크.
2. 상태 표(정상, 로딩, 비어 있음, 오류)와 각 상태의 한국어 문구.
3. 컴포넌트 매핑: 어떤 기존 컴포넌트(`marker`, `attachment`, `alert`, `badge`, `button`)를 쓰고, 새로 필요한 컴포넌트가 있다면 이유와 variant. 토큰은 `--fm-*`만 쓰고 새 색이 필요하면 의미를 먼저 제안.
4. 규칙과 충돌하는 부분의 목록과 제안(특히 3.4의 허용 버튼, 3.3의 `literal_mismatch` 색).
5. 접근성: 키보드 순서, 포커스, 상태를 색에만 의존하지 않는 표시(아이콘/텍스트), 대비 기준.

## 5. 하지 않는 것

- 헤더·패널에 장식, 로고, 구분선 추가
- 평가·통계 대시보드(내부 측정용이며 UI가 아님)
- 모바일 레이아웃(데스크톱 전용)
- 사용자가 승인하지 않은 상태에서 Vault에 쓰는 흐름
- 자동으로 provider를 바꾸는 흐름(항상 사용자에게 제시)
