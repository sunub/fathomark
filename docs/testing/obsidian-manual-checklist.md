# Obsidian 수동 확인 체크리스트

자동 테스트와 실제 모델 평가(`plugin/tests/career-eval.test.ts`, `meaning-eval.test.ts`)로 확인할 수 없는 실제 앱 동작을 확인한다. 에디터 선택, 미리보기 적용, 문서 변경 감지, 되돌리기, 백그라운드 색인은 Obsidian 안에서만 볼 수 있다. 기준 문서는 [verification.md](../design/workflow/verification.md)다.

## 준비

1. Ollama를 실행하고 `gemma4:e4b`와 `bge-m3`가 설치돼 있는지 확인한다(`ollama list`).
2. 저장소 루트에서 테스트 Vault를 만든다. 합성 fixture 노트만 들어가며 기존 폴더는 덮어쓰지 않는다.
   ```bash
   node scripts/prepare-test-vault.mjs ~/vaults/fathomark-check
   ```
3. Obsidian에서 해당 폴더를 Vault로 열고, 요청이 나오면 커뮤니티 플러그인을 켠다. 리본의 Fathomark 아이콘으로 패널을 연다.

각 항목은 통과·실패와 관찰 내용을 기록한다. 실패하면 개발자 콘솔(`Cmd+Opt+I`) 오류도 함께 남긴다.

## 항목

| # | 조작 | 통과 조건 |
|---|---|---|
| 1 | 설정 → Semantic search 설명 확인. Obsidian 시작 후 1분 기다림 | 오류 문구 없음. `.obsidian/plugins/fathomark/vector-index.json` 생성 |
| 2 | `자기소개서.md` 끝에 커서를 두고 "문항에 맞춰 500자 내외로 써줘" 요청 | 단계 표시가 분석→탐색→…→미리보기 순서. `경험/상품조회-캐시-도입.md`가 출처에 표시. 노트는 아직 변경되지 않음 |
| 3 | 2의 미리보기에서 Approve | 커서 위치에 한 번만 삽입. 같은 미리보기 재승인 불가 |
| 4 | 3을 `Cmd+Z`로 되돌림 | 삽입 전 상태로 복구 |
| 5 | 새 요청 후 미리보기가 뜨면, 승인 전에 노트를 직접 수정하고 Approve | 적용되지 않고 "문서가 바뀌었습니다" 표시 |
| 6 | 5에서 Recreate preview | 미리보기가 조용히 사라지지 않고 재실행·재검증 안내 표시 |
| 7 | 미리보기를 Discard | 노트 변경 없음. 미리보기 버튼 다시 사용 가능 |
| 8 | 초안이 나온 뒤(적용 전) "더 짧게" 요청 | 탐색 없이 같은 출처로 더 짧은 초안. 같은 위치에 새 미리보기 |
| 9 | 8의 초안을 적용한 뒤 아무것도 선택하지 않고 "더 짧게" 요청 | 이전 초안이 아닌 노트 문단을 대상으로 다룸(문단 선택 요청 또는 자동 대상) |
| 10 | "블록체인 스마트 컨트랙트 경험을 써줘" 요청, 질문이 오면 "모릅니다" 답변 | 질문 대기 중 경과 시간 정지. 초안·미리보기 없이 미완료 |
| 11 | 질문 대기 중 Stop | 취소 상태. 이후 늦은 답변 입력이 반영되지 않음 |
| 12 | 문단 하나를 선택하고 "숫자는 유지하고 더 간결하게" 요청 | 선택 문단만 대상. 수치 유지. 승인 전 노트 변경 없음 |
| 13 | 설정에서 Semantic search를 끄고 2를 다시 요청 | 키워드 검색만으로 동작. 오류 없음 |
| 14 | `ollama stop` 또는 Ollama 종료 후 요청 | "로컬 모델에 연결할 수 없습니다" 안내. 앱 멈춤 없음 |
| 15 | Obsidian 재시작 | 이전 대기·미리보기가 자동 실행·승인되지 않음. 색인은 바뀐 노트만 다시 계산 |

## 기록

결과는 날짜, Obsidian 버전, 모델 digest(`ollama show gemma4:e4b`)와 함께 `reports/`에 남긴다. 실제 개인 Vault로 반복할 때는 노트 제목과 본문을 기록에 넣지 않는다.
