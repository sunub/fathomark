# S9: Deep Agents 재검토 (조건부)

**목표**: Deep Agents를 도입할 조건이 갖춰졌는지만 판정한다. 조건이 안 되면 구현하지 않고 이 문서에 사유를 갱신한다.

**선행**: S4 완료. **프레임워크**: Deep Agents(`deepagents`).

## 현재 도입하지 않는 이유 (조사 결과)

- 번들: 단독 1,800 KB로 core 대비 +약 0.8 MB, LangGraph 대비 +약 0.5 MB(예산 900 KB와 비교).
- 의존성: `zod` 4 필요, 현재 플러그인은 zod 3.
- 도구: 기본 도구에 `write_file`, `edit_file`, `delete`가 있고 FilesystemMiddleware와 SubAgentMiddleware는 제외할 수 없다. `permissions`로 쓰기를 deny할 수는 있어도 도구는 모델에 노출된다. Vault 읽기 전용 원칙과 충돌한다.
- 제품 방향: ADR 0007은 열린 루프 대신 고정 단계를 선택했다. Deep Agents는 열린 계획·서브에이전트 용도라서 고정 워크플로 전체에는 맞지 않는다.
- 기본 시스템 프롬프트가 붙는지, 크기가 얼마인지는 확인 못함(추정 1~2.5K 토큰).

## 재검토 조건 (모두 충족 시 스파이크 진행)

1. S4가 끝났고, 열린 탐색(여러 노트를 넘나드는 검색)에서 고정 단계 + createAgent가 평가 지표로 목표에 못 미친다는 측정이 있다.
2. 쓰기 도구를 모델에 노출하지 않는 방법(도구 제거 또는 읽기 전용 backend)이 공식 옵션으로 확인된다.
3. zod 4 승격이 별도 슬라이스로 완료되었고, 번들 예산 결정(S0)이 Deep Agents 증가분을 허용한다.

## 스파이크 범위 (조건 충족 시)

- 서브에이전트 하나가 읽기 전용 Vault 도구로 "경험 노트 후보 수집"만 수행하는 검색 서브에이전트를 시험한다. 컨텍스트 격리와 호출 수·토큰을 측정한다.
- S1의 고정셋에서 recall@3과 호출당 토큰을 S4 기본 방식과 비교한다.
