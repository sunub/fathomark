# 모델과 글쓰기 흐름 연결 구현

사용자가 앞서 검토한 흐름과 자동 대상 탐색 방향을 직접 구현하도록 승인했다. 기존 미커밋 작업을 보존하고 새 의존성 없이 구현한다.

## 범위와 소유권

- 실제 로컬 모델과 구조화 호출: providers/structured.ts, ollama.ts, 정직하게 표시한 로컬 입력량 추정. 모델 파일 다운로드·학습은 수행하지 않는다.
- 원문·숫자·출처 검사: context/claims.ts, copy-check.ts. 의미 판단은 별도 모델 검토이며 오류가 없다는 보증이 아니다.
- 자동 수정 대상: workflow/targets.ts, 기존 request.ts. 모델은 후보 ID만 선택하고 위치·원문은 코드가 가져온다.
- 작성 조정: workflow/career-graph.ts, state.ts. 기존 도구 실행기를 통해 읽기, 같은 실행의 질문 대기·재개, 근거 부족 차단, 초안 수정 최대 1회.
- 앱 연결: Harness, 이벤트·세션, main, chat-view, 질문·공고 입력과 검증된 미리보기. 기존 PreviewController의 대상 검사·중복 승인 보호 재사용.

## 실행 순서

1. 기존 검사 기준선 확인. 기능별 실패 테스트를 먼저 실행한다.
2. 원본 근거 형식·상태·이벤트 계약 연결, 모델·도구 예산 검사.
3. 작성 흐름과 Harness 대기·재개를 연결한다. 타이머는 사람 대기 중 중지하고 누적 사용량 유지.
4. 실제 모델 설정·붙여넣기·자동 대상·질문·검증 결과를 화면에 연결한다.
5. 독립 리뷰와 전체 typecheck, tests, boundaries, build. 외부 모델 제공자·일반 웹·선택적 작업 메모·영속 복구는 확장하지 않는다.

## 고정할 완료 조건

- 입력은 분석된 조건으로 진행하고 모호하면 질문한다. 선택 문단이 있다고 새 글 요청을 수정으로 분류하지 않는다.
- 모델·도구·질문·자료 길이는 유한하다. 도구 없는 탐색 응답은 작성 가능성 검사로 이동한다.
- 근거·충돌 해결이 안 되면 초안/미리보기 생성 0회.
- 질문은 실행·질문 ID에 묶고 대기 중 모델·도구 추가 호출 0회. 취소/늦은/중복 답변 거부.
- 초안의 경험 주장은 실제 원문 또는 이번 실행 사용자 답변에만 연결한다. 공개 자료·문체는 경험 근거로 허용하지 않는다.
- 구조·의미·문체 검증 후 수정 초안 최대 1회, 실패하면 미완료. 최종 검증 결과만 미리보기로 전달.
- 자동 대상의 원문/위치는 신뢰된 노트 스냅샷에서 결정하고 적용 시 전체 문서·선택 상태 확인. 승인 전 쓰기 0회, 적용 최대 1회.
- 실제 모델 접속 여부와 모델 품질/실제 Obsidian 시험은 자동 모의시험과 구분해 보고한다.
