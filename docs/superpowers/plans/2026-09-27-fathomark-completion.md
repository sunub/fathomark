# Fathomark Completion Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 초기 골격과 학습 실험을 검증 가능한 노트 대화·승인 삽입 제품으로 연결하고, 실측하지 않은 모델 성능은 합격으로 표시하지 않는다.

**Architecture:** 기존 TypeScript 플러그인과 선택적 Python 학습 작업 공간의 경계를 유지한다. 런타임, 작성 UX, 모델 평가 무결성, 실제 제품 검증을 별도 계획으로 나누며 공유 인터페이스 변경은 리더 한 명이 통합한다.

**Tech Stack:** 기존 TypeScript/React 19/Zod/Vitest/Obsidian, Python/PyTorch/Transformers/unittest/Ruff. LangChain은 문서상 요구되지만 아직 설치되지 않은 의존성이다.

**Spec:** `docs/PRODUCT.md`, `docs/ARCHITECTURE.md`, `docs/MODEL_SELECTION.md`, `docs/ROADMAP.md`, `docs/adr/0001-obsidian-native-product.md`부터 `0006-user-selected-style-personalization.md`, 이번 대화의 코드 리뷰. 폴더 학습의 최신 승인 의도는 `.omx/plans/folder-to-evaluated-model.md`이며 아래 결정 기록에도 보존한다.

## Global Constraints

- Desktop-only Obsidian plugin. Python을 플러그인 설치 요구사항에 추가하지 않는다.
- No new dependencies without explicit request. 계획 작성은 패키지 설치나 제품 기본값 승인으로 간주하지 않는다.
- No Vault file changes before explicit approval. 삽입은 모델 도구가 아닌 사용자 동작이다.
- Wikipedia 외 일반 웹 검색, 외부 모델, 자동 다중 노트 편집, 별도 상주 프로세스는 범위 밖이다.
- 모든 작업은 기존 동작을 보호하는 실패 테스트 → 최소 구현 → 통과 확인 → 독립 리뷰 순서다.
- 최종 플러그인 검증: `pnpm typecheck && pnpm test && pnpm boundaries && pnpm build`.
- 최종 모델 검증: `cd model && .venv/bin/python -m unittest discover -s tests && .venv/bin/ruff check . && .venv/bin/ruff format --check .`.
- 기존 환경이 없으면 잠금 파일에 맞는 환경 준비까지만 진행하고, 설치 권한·네트워크 실패를 테스트 실패와 구분한다. 새 버전으로 임의 업그레이드하지 않는다.
- 코드 변경·공유 인터페이스·문서 결정은 요청 범위 안에서만 수행한다. 기존 사용자 변경을 덮어쓰지 않는다.

## 1. 현재 기준선과 해석

2026-09-27 검토에서 플러그인 24개 테스트, 타입·경계·빌드 검사와 모델 97개 테스트 및 Ruff가 통과했다. `main.js`는 약 286 KB다. 이는 새 실행 시 다시 확인할 기준선이며 실제 모델 품질의 증거가 아니다.

💡 하네스는 모델 호출·도구 권한·취소·예산·실행 상태를 통제하는 코드다. LoRA는 기본 모델을 유지하면서 작은 추가 가중치를 학습하는 방식이다. 비학습 기준선은 추가 학습 없이 지시와 문체 예시만으로 생성한 비교 대상이다.

- `plugin/`은 가짜 제공자와 빈 도구 목록을 사용한다. Phase 0 잔여와 Phase 1/2를 구현해야 한다.
- `model/`의 폴더 선택 → 자동 자료 생성 → 학습 → 검토 대기 흐름은 이미 승인된 실험 경로다. 자동 생성 자료가 미검토라는 이유만으로 제거하지 않는다.
- ADR 0003은 proposed다. 실험 코드 존재와 제품 학습 기능 채택은 별개다.
- 임베딩·외부 모델·다중 노트 편집 부재는 결함이 아니므로 이번 작업에 추가하지 않는다.

## 3. 추가 지시 없이 사용할 실행 기본값

아래는 **이 계획을 실행할 때의 보수적 제안**이다. 기존 accepted 기준을 덮어쓰거나 제품 기본 모델을 확정하지 않는다.

| 결정 | 실행 기본값 | 근거/후속 조건 |
|---|---|---|
| 최초 제공자 | Ollama native 어댑터 구현 | 현 설정의 `127.0.0.1:11434`를 활용. 모델명은 사용자가 설치한 모델 목록에서 명시 선택; 자동 다운로드 없음 |
| 네트워크 | 연구 기본 OFF; 모델 서버는 루프백만 | 사용자 이름/비밀번호, 비루프백 host, redirect 거부 |
| Wikipedia 질의 | 사용자가 직접 입력한 별도 공개 주제만 허용 | 모델·노트·문체 예시에서 질의를 자동 생성하지 않음 |
| 문맥 값 | 기존 `PROPOSED_LIMITS` 16000/8000/1400/256 유지 | 제품 채택 아님. 신뢰 가능한 상한 계산을 검증 못 한 모델은 지원 미확인 처리 |
| 실행 제한 | 전체 120초, 모델 호출당 60초, 도구당 10초 | 취소 후 늦은 결과 무시. 자동 재전송 없음 |
| 도구 제한 | 도구별 5회, 전체 12회, 모델 라운드 8회 | 한도 초과는 전체 실행을 불완전 종료; 반복 이벤트 무한 소비 금지 |
| 대화 보관 | 메모리 내 최근 10개 완료 대화 | 재열기 유지, 플러그인 종료 시 삭제; 각 요청은 별도 예산 적용 |
| 문체 자료 | 사용자가 직접 선택한 한 구절, 최대 UTF-8 4096 bytes | 자동 Vault 스캔 없음. 기본은 세션 한정, 장기 보관은 명시 저장 시만 |
| 삽입 | 생성 요청 당시 문서와 범위에 대한 단일 편집 | 현재 커서로 대체하지 않음; 본문이 바뀌면 미리보기 재작성 |
| 개인 학습 | 현재 후보 생성/검토 절차만 유지 | 자동 활성화 없음. 실측 전 제품 UI의 학습 적용 기능은 보류 |

16GB 메모리 상한·문체 선호 통계 기준·최종 출력 길이는 측정 전 임의 accepted 값으로 만들지 않는다. V2/V3가 보고서와 제안을 작성하되 미결정 상태를 보존한다.

## 4. 병렬 실행과 통합 순서

```text
시작 → P0 계약/기준선
       ├─ M1 → M2 → M3 → M4 (model 담당)
       ├─ P1 → P2 → P5 (하네스 담당)
       ├─ P3 제공자 (독립 담당)
       └─ P4 검색 (독립 담당)
P2+P3+P4+P5 → P6 연구 → P7 통합 (A1도 필요)
P0+P1 → A1 화면
P2+A1 → A2 문체
A1 → A3 승인 삽입
P7+A2+A3 → A4 전체 사용 흐름
계약 확정 후 V1 평가 자료는 병렬 작성 가능
P7+A4+M2+V1 → V2 실측 → V3 문서/출시 판정
```

- 권장 동시 작업자 수는 3명 + 리더다. 최대 6명을 채우기 위해 작업을 인위적으로 쪼개지 않는다.
- 역할은 구현 담당, 모델 담당, 독립 도구/제공자 담당으로 시작한다. 파일이 겹치는 P1/P2/P5는 병렬 금지다.
- 각 하위 작업에 작업 ID, 소유 파일, 선행 계약, 테스트 명령, 수정 금지 파일, 산출물 기준을 전달한다. 다른 작업자 변경을 되돌리지 않도록 명시한다.
- 완료 보고는 변경 파일/명령/실제 결과/남은 제한을 포함한다. 리더가 결과를 확인한 뒤 다음 의존 작업을 시작한다.
- 독립 리뷰어는 작업별 요구사항 충족과 결함을 확인한다. 리뷰가 직접 구현을 겸하지 않게 한다.
- 새 세션은 이 파일과 각 계획의 체크박스·검증 기록을 읽어 재개한다. 체크박스는 명령 결과 확인 후에만 완료 처리한다.

## 6. 커밋·검증·상태 규칙

- 이번 산출물은 계획 문서다. 제품 코드 실행·수정·의존성 추가·커밋·푸시·배포는 이 계획 작성에 포함하지 않는다.
- 후속 구현의 각 Task 마지막 Commit 단계는 리더가 수행한다. 병렬 작업자가 공유 Git 인덱스를 동시에 수정하지 않는다.
- `.agents/skills/commit/SKILL.md`를 사용하고 한국어 conventional header와 bullet, 관련 `Tested:`, `Not-tested:`, `Confidence:`, `Scope-risk:` trailer를 남긴다. 메시지 파일을 lint 후 `git commit -F`한다.
- 해당 스킬의 중첩 저장소 설명은 현재 상태와 다를 수 있다. `git ls-files`, `git -C model rev-parse --show-toplevel`로 실제 경계를 확인하고, 스킬 설명만 보고 ignore나 저장소 구조를 바꾸지 않는다.
- 리팩터링이 필요한 작업은 실패 회귀 테스트와 간단한 변경 계획을 먼저 기록한다. 새 추상화보다 기존 함수와 자료형 재사용을 우선한다.
- 순수 플러그인 변경에는 필수 4종 검사, 모델 변경에는 모델 3종 검사, 통합 이정표에는 둘 다 실행한다. TypeScript용 lint가 현재 없다는 이유로 도구를 새로 설치하지 않는다.
- 실행 결과는 각 계획 하단에 `작업 ID / commit / 명령 / 결과 / 환경 / 제한`으로 누적한다. 실제 개인 자료·답변·노트 경로는 저장소에 커밋하지 않는다.
