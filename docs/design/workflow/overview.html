제품 목표·용어·현재 구현 상태

상태: 설계 초안 · 구현 전
기준일: 2026-10-11
문서 목차

이 문서는 대화에서 정리한 전체 흐름, 실행 방식 선택, Harness와 Agent Loop, 기존·제안 도구, 자료 경계와 검증 계획을 모은다. 이미지는 제안 구조를 설명하는 것으로, 구현 완료나 특정 프레임워크 채택을 뜻하지 않는다. Obsidian CLI 도입은 후속 검토로 미룬다.

용어와 구현 상태

💡 워크플로우: 작업 단계와 통과 조건을 제품 코드가 정한 실행 순서다. 모델을 사용하더라도 다음 단계가 정해져 있으면 워크플로우다.

💡 에이전트: 관측한 결과에 따라 모델이 다음 행동을 선택하는 실행 방식이다. Harness가 허용한 범위에서 검색·읽기·질문 등을 제안한다.

💡 Harness: 모델 호출, 도구 권한, 실행 한도, 상태, 취소와 승인을 관리하는 제품 측 실행 코드다. Loop는 행동 결과를 다시 입력받아 다음 행동을 결정하는 반복 과정이다.

💡 도구: 노트·공개 자료·사용자 입력처럼 모델 밖의 정보나 기능에 접근하는 인터페이스다. 작성 절차는 문항 분석·개요 비교·비평처럼 확보한 정보를 다루는 재사용 가능한 모델 작업이다.

현재 코드와 목표 설계를 구분해야 한다. 플러그인 진입점은 빈 도구 등록 목록과 FakeModelProvider를 사용한다. Vault·Wikipedia 도구 모듈과 Loop, 미리보기 기능이 존재하더라도 실제 앱에 이번 커리어 흐름이 연결됐다는 뜻은 아니다.

구분 현재 상태 이번 문서의 방향
search_vault, read_note 기존 도구 모듈 경험 탐색에 재사용하고 실행 경로 연결
search_wikipedia, read_wikipedia_page 기존 도구 모듈 공개 배경 자료 조사 기능으로 범위 유지
모델·도구 반복과 호출 한도 기존 코드 단계별 허용 도구와 명시적 종료 계약 추가
문체 선택·미리보기·에디터 적용 관련 기능 존재 검증된 초안과 승인 경계에 연결
여섯 제안 도구 구현 전 입력·출력·실패·권한 계약 설계
주장과 원문의 의미 일치 검증 계획 단계 필수 검증 단계로 구체화
