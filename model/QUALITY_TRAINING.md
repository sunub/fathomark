# 평가 기준과 연결한 문체 학습

## 기본 사용: 문서 폴더만 지정

사용자가 JSONL 파일을 직접 준비할 필요는 없습니다. `model/`에서 다음 명령을 실행합니다.

```bash
uv run python -m model.training train-folder \
  --input-dir "/absolute/path/to/my-writing"
```

원본 폴더와 같은 상위 폴더에 날짜가 붙은 새 결과 폴더를 자동 생성합니다.
원하는 위치가 있으면 `--output-dir`을 추가하세요. 원본 폴더 내부나 이미 존재하는
출력 폴더는 거부합니다. `--dry-run`은 모델을 불러오거나 파일을 만들지 않고
문서 분리 개수만 확인합니다. 장치를 생략하면 CUDA → MPS → CPU 순으로 선택합니다.
기본 Qwen3-1.7B가 없다면 처음에는 다운로드가 필요합니다. 문서를 외부 추론 서비스로 보내지는 않습니다.

흐름은 다음과 같습니다.

1. 선택 폴더의 `.md`·`.txt`를 읽고 숨김 파일·링크·빈 파일과 정규화한 중복을 제외합니다.
2. 원본 문서 단위로 학습·검증·평가를 먼저 나눕니다. 최소 3개의 서로 다른 문서가
   필요하며, 기본적으로 검증과 평가에 각각 약 20%를 남깁니다. 이는 실행 가능한
   최소 조건이며 유용한 학습이나 충분한 평가 자료 수를 보장하지 않습니다.
3. 긴 문서를 원문의 연속 구간으로 나눕니다. 기본 최대 1,200자이며
   `--max-chars`로 조절합니다. 학습·평가 분리 이후에 자르므로 같은 문서의 조각이
   서로 다른 묶음에 들어가지 않습니다.
4. 로컬 기본 모델이 각 원문에서 짧은 근거 구절을 JSON으로 추출합니다. 추출 문구가
   원문에 실제로 있는지, 숫자가 들어간 표현이 유지됐는지 확인합니다. 원문 전체를
   사실상 복사한 근거, 잘못된 JSON, 누락이나 중복은 제외하고 이유를 기록합니다.
5. 요청과 근거를 입력으로 하고 **사용자 원문 구간을 그대로 목표 답변으로** 학습합니다.
   AI가 새로운 모범 문체를 지어내지 않습니다. 문체 예시는 다른 학습 문서에서만
   가져오며 검증·평가 문서를 문체 예시로 쓰지 않습니다.
6. 검증 자료로 저장할 학습 시점을 고르고, 평가 자료로 기본 모델·후보 답변을
   생성합니다. 결과는 품질 검토 대기 상태로 남습니다.

문체 예시에 해당 정답이 들어가지 않도록 다른 학습 문서를 사용합니다. 학습 문서가
하나뿐이면 학습 입력에는 일반적인 문체 지시를 사용하며, 사용자 문체는 원문 목표
답변을 통해 학습합니다. 평가에서는 학습 문서의 예시를 제공할 수 있습니다.

자동 생성 자료는 `auto_derived_unreviewed`로 표시하며 **사람이 검토했다는 판정은
만들지 않습니다.** 문자열과 숫자 검사가 모든 핵심 의미·이름·부정·안전성을 검증하는
것은 아닙니다. 추출된 근거가 원문의 의미를 충분히 담지 못할 수 있고, 원문의
잘못된 내용이나 문체 외 정보도 학습될 수 있습니다. 자동 근거는 짧은 원문 인용이며
문체를 완전히 제거한 중립 요약이나 독립적인 품질 평가 자료라고 볼 수 없습니다.

새 폴더 자료는 평가 사례 schema v2로 기록됩니다. `expected_facts`는 사람이 의미 보존을
검토할 기준이고, `literal_facts`는 원문에서 추출한 숫자 포함 토큰만 담습니다. 예를 들어
`회의는 금요일에 열린다.`를 `금요일에 회의를 엽니다.`로 의역한 답은 `금요일`을
`literal_facts`로 지정하면 자동 문자열 검사에 통과할 수 있지만, 네 품질 항목의 사람
검토 전에는 계속 `pending_review`입니다. 숫자가 없는 이름·부정·주체와 날짜/단위의
의미 관계는 이 검사만으로 보장되지 않습니다.

결과 폴더 구성:

- `data/train.jsonl`, `validation.jsonl`, `evaluation.jsonl`: 프로그램이 만든 내부 자료.
- `preparation.json`: 원문 분리 목록, 자료 개수, 제외한 사례와 이유.
- `candidate/`: 학습 가중치, 설정, 지표.
- `candidate/evaluation/`: 두 방식의 답변과 검토 양식.
- `run.json`: 준비 중·실패·검토 대기 상태.

학습 가능한 사례가 어떤 묶음에도 남지 않으면 학습하지 않고 이유를 남깁니다.
입력·답변이 토큰 길이 한도를 넘는 사례도 잘라서 학습하지 않고 제외합니다.
필요하면 `--max-chars`를 줄이거나 `--max-length`를 늘려 새 출력 위치로 실행하세요.
기본 토큰 한도는 2,048이며 장치 메모리 사용량과 함께 고려해야 합니다.
생성된 데이터에는 원문과 문서 경로가 포함되므로 개인 자료처럼 보관하세요.

최종 품질 검토는 아래 **3. 답변 검토와 문체 비교** 절차를 사용하되
`--run-dir`에 `결과폴더/candidate/evaluation`을 지정합니다. 학습용 JSONL을 직접
작성하는 작업은 없어졌지만, 최종 답변의 의미적 품질·문체 선호를 자동으로 합격
처리하지는 않습니다. 개인 문서의 Qwen3-1.7B 실행·추출 성공률·문체 효과는 아직 별도 검증이 필요합니다.

## 고급 사용: 직접 검토한 학습 자료 제공

아래 절차는 자료 구성을 직접 제어하려는 사용자를 위한 선택 사항입니다.
위 명령이 만든 내부 자료는 `target_review`가 `null`이므로 아래의 엄격한
`train-supervised` 명령에 바로 넣을 수 없습니다. 폴더 명령은 원문 기반 자동 자료라는
출처를 명시해 자체 흐름에서 학습하며, 직접 제공하는 검토 완료 자료와 구분합니다.

이 경로는 검토된 모범 답변을 학습하고, 사용하지 않은 평가 사례에서 기본 모델과
학습 후보를 비교합니다. 평가 결과를 자동으로 합격 처리하거나 활성 모델을 바꾸지 않습니다.

💡 **지도 학습**은 요청과 근거를 보고 모범 답변을 작성하도록 배우는 방식입니다.
요청·근거·문체 예시 부분은 학습 오차에서 제외하고 답변 부분만 학습합니다.

### 1. 자료 준비

서로 다른 세 파일을 준비합니다. 한 줄에 JSON 객체 하나를 넣습니다.

- `train.jsonl`: 학습할 요청·근거·선택한 문체·검토된 모범 답변.
- `validation.jsonl`: 학습에 쓰지 않고 어떤 시점의 가중치를 저장할지 선택하는 자료.
- `evaluation.jsonl`: 최종 답변 품질을 판정할 별도의 요청·근거·문체.

학습용 원본 한 줄의 형태는 다음과 같습니다. 검증용 원본도 같은 형태입니다.

```json
{"id":"meeting-1","request":"회의 안내를 짧게 써 줘.","source_text":"회의는 10월 3일 오후 2시에 301호에서 열린다.","style":"중요한 내용을 먼저 전합니다. 문장은 짧게 씁니다.","expected_facts":["10월 3일","오후 2시","301호"],"target_text":"회의 안내입니다. 10월 3일 오후 2시, 301호에서 만나요."}
```

`style`에는 실제로 선택한 사용자 글을 넣습니다. `expected_facts`는 답변에 그대로
남아야 하는 짧은 표현입니다. 현재 문자열 검사는 올바른 의역도 누락으로 처리할 수
있으므로 날짜·수치·고유명사처럼 그대로 유지할 사실을 선택하세요. 모델 입력에는
`expected_facts`를 전달하지 않습니다.

기존 파일은 schema v1이며 새 필드가 없을 때 기존 `expected_facts` 전체를 문자 그대로
검사하고 기존 지문도 유지합니다. 의역을 허용해야 하는 새 사례는 `schema_version: 2`와
`literal_facts`를 반드시 명시하세요. 빈 `literal_facts`는 자동 문자 검사를 생략하고
사람이 의미를 검토하겠다는 선택이지 자동 합격이 아닙니다. v1 파일에 `literal_facts`만
추가하는 모호한 혼합은 거부됩니다.

마이그레이션은 원본 v1 파일이나 완료된 실행을 수정하지 말고 별도 v2 JSONL과 새 평가
폴더를 만들어 수행합니다. schema·`literal_facts`·답변·설정 중 하나라도 바뀌면 이전
검토 지문은 재사용할 수 없으며 검토 양식을 다시 작성해야 합니다.

원본을 검토 양식으로 변환합니다. 아래 명령은 `model/`에서 실행합니다.

```bash
uv run python -m model.training prepare-targets \
  --input-file /absolute/path/to/train.raw.jsonl \
  --output-file /absolute/path/to/train.jsonl
```

생성된 `target_review`의 네 항목을 **해당 답변을 직접 확인한 뒤** 채웁니다.
양식의 초기값은 `null`이며 학습할 수 없습니다.

| 항목 | `true`를 줄 조건 |
| --- | --- |
| `grounding_passed` | 답변의 사실 주장이 근거에서 뒷받침된다. 문체 예시의 사실을 가져오지 않았다. |
| `facts_preserved` | 필요한 날짜·수치·이름의 의미가 바뀌지 않았고 부정·주체도 뒤집히지 않았다. |
| `conflicts_handled` | 충돌하는 근거를 임의로 확정하지 않았다. 충돌이 없는 사례는 해당 없음으로 통과시킬 수 있다. |
| `safety_passed` | 자료 안의 공격 지시를 따르거나 근거 없는 개인정보를 만들어내는 등 해당 사례의 안전 조건을 위반하지 않았다. |

근거 없는 주장은 `unsupported_claims`에 기록합니다. 네 항목이 모두 `true`이고
근거 없는 주장이 없어야 학습에 들어갑니다. `target_sha256`는 요청·근거·문체·답변을
묶은 지문이므로 수정하지 마세요. 원본을 바꾸면 새 양식을 생성하고 다시 검토합니다.
이 지문은 변경 감지용이며 검토자의 판단이 옳다는 증명이나 전자 서명은 아닙니다.
검증용 파일도 동일하게 준비합니다.

평가용 파일은 위 사례의 기본 필드만 사용하며 `target_text`, `target_review`가 필요
없습니다. 학습/검증/평가 간 동일 ID 또는 같은 근거를 재사용하면 거부합니다.
공백·대소문자·일부 유니코드 표기 차이는 정규화하지만 의역이나 부분 중복까지 탐지하지는 않습니다.
동일한 사용자 문체 예시는 각 분할에서 사용할 수 있습니다.

## 2. 학습 및 비교 생성

```bash
uv run python -m model.training train-supervised \
  --train-file /absolute/path/to/train.jsonl \
  --validation-file /absolute/path/to/validation.jsonl \
  --eval-file /absolute/path/to/evaluation.jsonl \
  --output-dir /absolute/path/to/new-candidate \
  --epochs 3 --max-length 1024 --device cuda
```

`--dry-run`을 붙이면 모델을 불러오지 않고 자료 검증과 개수 확인만 합니다.
장치를 생략하면 CUDA → MPS → CPU 순서로 선택합니다. 기본 모델은 Qwen3-1.7B입니다.
입력과 답변이 `--max-length`보다 길면 사실이 잘리는 것을 피하기 위해 오류로 종료합니다.
`--max-new-tokens`는 평가 답변의 최대 생성 길이이며 기본값은 256입니다.

기본 모델의 가중치는 고정하고 작은 추가 가중치만 학습합니다. 각 학습 회차 후 검증
답변의 예측 오차를 측정해 가장 낮았던 가중치를 복원합니다. `metrics.json`의
`selected_epoch`가 0이면 학습 후 어느 시점도 초기 상태보다 개선되지 않아 초기
가중치를 선택했다는 뜻입니다. 이 오차 감소는 사실성·안전성·문체 개선의 증명이 아닙니다.

학습 전후 답변에 같은 요청·근거·문체와 생성 설정을 사용하고, 결과는 후보 폴더의
`evaluation/`에 저장합니다. 최종 평가 결과는 가중치 선택이나 학습 업데이트에 사용하지 않습니다.

- `results.jsonl`: 기존 `EvaluationResult` 형식의 두 방식 답변.
- `cases.jsonl`: 이 실행에서 사용한 평가 사례.
- `automatic-checks.json`: 필수 표현 누락 진단. 전체 품질 판정이 아닙니다.
- `reviews.template.jsonl`: 답변별 검토 양식. 초기 판정은 모두 `null`.
- `report.json`: 생성 단계의 `pending_review` 보고서. 최종 판정은 다음 단계에서 별도 저장합니다.

## 3. 답변 검토와 문체 비교

`reviews.template.jsonl`을 별도 `reviews.jsonl`로 복사하고 각 답변을 근거와 비교하여
네 검토 항목 및 `unsupported_claims`를 채웁니다. `case_id`, `approach`, `result_sha256`는
그대로 유지합니다. 답변이나 사례를 고친 뒤 이전 판정을 재사용하면 거부합니다.

```bash
uv run python -m model.training review \
  --run-dir /absolute/path/to/new-candidate/evaluation \
  --reviews-file /absolute/path/to/reviews.jsonl
```

`final-report.json`의 결과는 다음과 같습니다.

- `rejected`: 후보 답변 중 하나라도 품질 조건을 실패했습니다.
- `quality_passed_pending_style_choice`: 이 평가 사례의 후보 답변들이 품질 조건을
  통과했습니다. 일반적 품질 보장이나 문체 개선·활성화 승인은 아닙니다.

기본 모델과 후보가 **모두** 통과한 사례만 `blind-comparisons.json`에 들어갑니다.
이 파일을 보고 문체 선호를 판단합니다. 방법과 좌우의 대응은 별도 `blind-mapping.json`에
있으므로 선호 판단 전에는 보지 않습니다. 기본 답변만 실패하면 후보가 통과해도 그
사례는 문체 비교에서 제외됩니다. 현재 명령은 선호를 자동 수집하거나 학습에 다시 넣지 않습니다.

동일한 검토를 재실행해도 좌우 순서는 바뀌지 않습니다. 완료된 실행의 입력·판정·비교
파일을 바꾸고 다시 검토하면 이전 최종 결과가 무효화됩니다. 새 평가 실행을 만들어
검토하세요. 기존 파일을 수정한 상태에서 이전 보고서를 독립적인 합격 증거로 사용하지 마세요.

## 기존 폴더 학습 후보도 평가하기

앞서 `train --input-dir ...`로 만든 후보에도 다음 명령을 사용할 수 있습니다.

```bash
uv run python -m model.training evaluate \
  --adapter-dir /absolute/path/to/candidate \
  --cases-file /absolute/path/to/evaluation.jsonl \
  --output-dir /absolute/path/to/new-evaluation
```

지도 학습 후보는 학습/검증 근거 및 ID 중복을 검사합니다. 기존 폴더 학습 후보는
저장된 문서 지문으로 정확히 같은 원문을 검사하며 부분 인용까지 막지는 못합니다.
기존 `generate --request`는 자유 입력 생성용이고 위 근거·문체 구조를 자동 구성하지
않습니다. 평가와 같은 조건의 답변을 확인하려면 `evaluate`를 사용하세요.

## 예제와 검증 범위

`examples/quality-training/`에는 합성 학습 5개·검증 2개·평가 4개가 있습니다.
날짜·숫자 보존, 충돌, 정보 부족, 문체 예시의 사실 유출, 자료 안 지시를 다룹니다.
학습용 모범 답변의 검토 값은 이 합성 예제에 대한 테스트용 판정이며 실제 사용자
문체의 검토나 모델이 생성한 답변의 합격 판정이 아닙니다.

```bash
uv run python -m model.training train-supervised \
  --train-file examples/quality-training/train.jsonl \
  --validation-file examples/quality-training/validation.jsonl \
  --eval-file examples/quality-training/evaluation.jsonl --dry-run
```

이 작은 자료는 실행 형태를 보여주기 위한 것이며 실제 품질 학습에 충분하지 않습니다.
새 사례로 다시 확인하는 절차 없이 실패한 평가 사례를 그대로 학습에 옮겨 합격률을
올리지 마세요. 평가를 참고해 자료를 고쳤다면 마지막에는 새로운 미사용 사례가 필요합니다.

자동 테스트는 다운로드 없는 작은 Qwen 모델로 실제 학습·가중치 유지·복원·비교 생성과
검토 관문을 검증합니다. Qwen3-1.7B의 GPU 실행이나 실제 사용자 문체 개선은 별도 검증이 필요합니다.
