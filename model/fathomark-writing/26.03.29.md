## [미로 탈출하기](https://www.acmicpc.net/problem/17090)

이 문제는 상태를 어떻게 관리하는지, 하나의 배열 내에서 상태를 어떻게 구분하여 관리하는지를 기준으로 해결해야 하는 문제였습니다. 처음에 이 문제를 해결하고자 했을 경우에 상태에 대한 값을 배열내에 다음과 같이 정의하여 해결하고자 했습니다.

```plaintext
-1 : 문제의 조건을 도달하지 못하는 경우
0 : 아직 방문하지 않은 경우
1 : 문제의 조건을 달성한 경우
```

위와 같이 상태를 정의하여 $R*C$ 의 배열내에 상태를 저장해가면서 문제를 해결하고자 했습니다. 이 문제를 해결할때 DFS를 사용하였기 때문에 위에서 정의한 배열 `visited` 배열이 필요하다고 판단하여 이 문제를 해결할때 $R*C$ 크기의 배열을 2가지를 사용하여 문제를 해결하였습니다.

물론 이렇게도 문제를 해결할 수 있었지만 이보다 더 좋은 방법은 1차원 배열로 변환하여 문제를 해결하는 것이었습니다.

```js
const one_dimension_number = i * C + j


function decode(num) {
	return [Math.floor(num / row), num % col];
}
```

이 후에 수행할 방법은 다음 인덱스의 상태에 대해서 저장하는 것이었습니다. 이 문제의 2차원 배열내의 요소는 다음 인덱스로 이동할 수 있는 방향 값이 주어졌기 때문에 현재 인덱스에서 다음 인덱스가 어떻게 될지에 대해서 결정할 수 있었습니다. 

```js
const next = new Int32Array(total);
if (nx < 0 || nx >= R || ny < 0 || ny >= C) {
  next[id] = -1;
} else {
  next[id] = nx * C + ny;
}
```

next 의 값을 추적하여 -1인 경우를 발견하게 된다면 해당 인덱스는 무조건 바깥으로 벗어난다는 것을 1차원 배열을 사용하여 표기할 수 있습니다. 이후에는 1차원으로 표현된 모든 좌표들을 탐색을 수행해야 합니다. 하지만 이 경우 탐색의 효율성을 높이기 위해서는 이미 탐색한 인덱스를 반복하여 방문해서는 안되기 때문에 방문 상태를 저장하여 관리해줘야 합니다.

```plaintext
// 0: 미방문, 1: 현재 경로 방문중, 2: 탈출 가능, 3: 탈출 불가
```

이 후에는 이 상태 값을 기준으로 모든 노드를 반복하는 것입니다.

```js
for(let node = 0; node < totalNode; node++) {
	if(state[node] !== 0) {
		continue;
	}
	
	let currNode = node;
	const paths = [];
}
```

위와 같이 현재 노드 값을 기준으로 모든 노드들을 탐색을 수행하고 state 의 방문상태를 확인하며 탐색을 수행합니다. 그리고 이 탐색 중에는 paths 의 대한 추적이 이루어져야 문제의 정답을 추적할 수 있기 때문에 탐색중 방문한 모든 노드값을 저장합니다.

```js
while(true) {
  if(currNode === -1) {
    for(const path of paths) {
      state[path] = 2;
    }

    answer += path.length;
    break;
  }

  const nextNode = nextIds[currNode];
  if(state[currNode] === 0) {
    path.push(currNode);
    state[currNode] = 1;
    currNode = nextNode;
    continue;
  }

  const result = state[nextNode] === 1 ? 3 : state[nextNode];
  for(const path of paths) {
    state[path] = result;
  }
  if(result === 2) {
    answer += paths.length;
  }
  break;
}
```

1. 현재의 노드 값이 -1 인 경우는 즉시 밖으로 나갈 수 있는 경우이기 때문에 더이상 탐색을 수행하지 않고 지금까지 방문한 값들을 탈출 가능한 상태로 업데이트하고 정답에 추가합니다.
2. 현재 노드에 대한 상태 값이 0인 경우 아직 방문을 하지 않은 상태이므로 탐색 중인 상태(아직 현재 노드의 상태가 오답인지 정답인지 결정이 되지 않았기 때문에) 로 업데이트 후 계속해서 탐색을 수행합니다.
3. 이미 방문한적이 있는 노드를 만났을 경우 해당 노드의 방문 상태가 불가능한 상태일 경우 지금까지 방문한 모든 노드 또한 정답이 불가능한 값이기 때문에 업데이트를하고 정답이 가능한 경우 정답이 가능한 경우로 모두 업데이트하여 마무리합니다.
