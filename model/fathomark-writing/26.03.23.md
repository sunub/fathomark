## [교환](https://www.acmicpc.net/problem/1039)

이 문제를 잘못 파악한 것은 입력값에 대한 조건을 잘못 생각했습니다. 이 문제의 조건은 수의 크기가 아닌 자릿수의 크기였기 때문에 1,000,000 이 최대 수인 입력 값이라고 하더라도 7자리의 수이기 때문에 입력 크기 제한이 7인 아주 작은 크기였기 때문에 Brute Force 로 해결이 가능한 수준이라는 것을 잘못 판단했습니다.

입력 값의 크기가 크기 때문에 $O(N)$ 이나 $ON(logN)$ 으로 해결을 해야 한다고 생각 했기 때문에 이 문제의 접근을 우선순위 큐와 그리디로 해결하고자 했습니다. 하지만 내가 생각한 방법으로 이 문제를 해결할 수 없는 이유는 최적의 상황을 보장할 수 없었기 때문입니다.

```plaintext
436659 2
```

위와 같이 중복되는 `66` 와 같이 동일한 크기의 숫자가 있을 경우 지금은 두 수가 붙어 있지만 서로 다른 자릿수에 위치하게 될 경우 어떠한 자릿수의 숫자를 먼저 가장 큰 수의 위치인, 왼쪽으로 배치해야 최대의 수를 만들 수 있을지에 대해서 알 수 없기 때문입니다.

그래서 이 문제는 모든 경우의 수를 고려해야 하는 문제였습니다. 이 문제는 BFS을 사용하여 문제를 해결해야 하는 문제였습니다. 이 문제에서 사용하는 BFS의 경우 기존과는 다른 방향으로 진행해야 합니다.

우리가 흔히 사용하던 BFS 의 경우 방향이 존재하고 좌표가 존재하지 않기 때문에 **Depth**를 기준으로 방문 상태와 현재 상태를 확장해나가면서 상태를 확인해야 합니다.

```js
const used = Array.from({ length: K + 1 }, () => new Set());
``` 

위와 같이 이 문제에서 주어지는 조건, Depth 는 **k의 값의 반복 횟수** 이기 때문에 위와 같이 방문 상태를 검사해가면서 BFS 를 적용해야 해결할 수 있는 문제였습니다.

언제나 느끼지만 알고리즘 문제는 문제를 잘 읽고 문제의 조건, 제약 조건, 문제의 조건을 꼼꼼하게 읽는 것이 가장 중요한 요소인것 같습니다.

## 이력서 내용 정리

현재 내 이력서에 빠져 있는 내용은 주로 사용자 경험을 어떻게 증진시켰는지에 대한 부분이 빠져있다. 대부분의 경험은 모두 결과적으로 어떠한 것을 만들어냈고 이 결과를 통해서 무엇이 좋아졌는지 어떤 부분이 개선되었는지에 대한 해석이 부족하다.

“누가 어느 순간 왜 불편했고, 그게 왜 제품 가치 손실이었으며, 나는 그 흐름을 어떻게 복구했는가” 에 대한 관점으로 새롭게 작성을 해보자

빠른 스크롤 시 발생하던 콘텐츠 로드 지연과 프레임 드랍을 개선해 Layout + UpdateLayoutTree 비용을 29.9%, 50ms 이상 Long Task 발생 빈도를 62.2% 줄여 연속 스크롤 중에도 더 끊김 없는 콘텐츠 탐색 경험을 제공하게끔 개선.

기존의 가상 스크롤 기반으로 작성되어 있던 무한 스크롤 기능을 전환
1. 무한 스크롤의 문제점은 무한 스클로 자체가 서비스의 컨텐츠를 사용자에게 더 탐색하게끔 유도하지 못한다.
2. 오히려 사용자들은 서비스 내에서 이용이 가능한 서비스에 대한 파악이 느려지고 관심이 없어지는 경우가 발생한다는[ 연구 결과](https://searchengineland.com/google-dropping-continuous-scroll-in-search-results-443529)가 있었다.
3. 무한 스크롤보다는 "더 보기"와 같은 버튼을 사용한 컨텐츠 로드 방식이 사용자에게 의도 전달이 더 명확하다.

이러한 단점이 존재한다는 것을 알았다. 실제로 블로그 서비스에서 가상 스크롤을 사용한 컨텐츠 로드방식은 블로그 메인페이지에서 컨텐츠를 로드하는 뱡향은 서비스의 목적에 적절하지 않다고 판단했다. 블로그에 방문하는 목적은 결국 전체 글을 보기 위한 것보다는 특정 글을 읽는 목적으로 접근하는 경우가 대부분이기 때문에 몇 개의 포스트를 강조하고 전체 글을 탐색하는 과정은 사용자의 의도가 명확할 경우로 제한하여 적용하는 것이 적절하다고 판단했다.

그래서 메인 페이지에는 몇개의 포스트를 강조하는 방법, 전체 포스트와 카테고리로 나뉘어진 포스트의 경우만 가상 스크롤을 적용한 전체 콘텐츠 탐색 방식으로 전환하여 사용자 경험을 증진시키고자 하였다.
