
## Deque

```js
stack.push(num);
stack.pop();

queue.push(num);
queue.shift();
```

Deque 는 기존의 알고 있던 stack 와 queue 와는 다른 접근 방법이 필요합니다. 기존의 stack 와 queue의 데이터 주입과 삽입의 순서는 정해져 있습니다. queue 의 경우 선입선출의 방법을 사용하고 stack 의 경우 후입선출의 방식으로 동작하여 일정 방향이 존재합니다.

하지만 Deque 의 경우 Deque(데크, Double-Ended Queue)는 **양방향에서 데이터를 삽입하거나 삭제할 수 있는 선형 자료구조** 로, 스택(Stack)과 큐(Queue)의 장점을 혼합한 구조입니다. 리스트(List)와 달리 앞/뒤 양끝에서의 추가(append)와 꺼내기(pop)를 $O(1)$의 빠른 속도로 처리하여 효율성이 높다는 특징을 갖고 있습니다. 이러한 특징으로 인해서 Deque 는 주로 슬라이딩 윈도우 구조, 단조 덱을 구현할 때 주로 사용이 됩니다.

### 슬라이딩 윈도우(단조 덱)에서 덱을 사용하는 이유

슬라이딩 윈도우의 문제의 경우 윈도우가 오른쪽으로 이동하면서, 범위를 벗어난(유통기한이 지난) 가장 오래된 인덱스를 맨 앞에서 버려야 합니다. 슬라이딩 윈도우의 경우 양방향의 제어가 필요했기 때문에  **양방향 제어를 동시에 제어할 수 있는** Deque 을 주로 사용하게 되었습니다.

이전 문제에서 일반 배열이나 단순한 큐가 아닌 '덱'을 사용한 이유는 **양방향 제어가 동시에 필요했기 때문**입니다.

- **앞(Front)에서 빼기 (`Pop Front` 적용):** 윈도우가 오른쪽으로 이동하면서, 범위를 벗어난(유통기한이 지난) 가장 오래된 인덱스를 맨 앞에서 버려야 합니다.
- **뒤(Back)에서 빼기 (`Pop Back` 적용):** 새로 들어올 값보다 큰 값들은 더 이상 최솟값이 될 가능성이 없으므로, 뒤에서부터 확인하며 모두 버려야 합니다.
- **뒤(Back)에 넣기 (`Push Back` 적용):** 쓸모없는 값을 정리한 후, 새로운 값을 뒤에 안전하게 추가합니다.

이렇게 양쪽 끝을 모두 조작해야 슬라이딩 윈도우의 최솟값을 $O(1)$에 찾을 수 있는 '단조 증가' 상태를 유지할 수 있습니다.

단조 증가(Monotonic Increasing)는 함수나 수열에서 변수나 항이 증가할 때 함숫값이나 항의 값이 감소하지 않고 같거나 커지는 성질(non-decreasing)을 의미합니다. 즉, $(x_1 < x_2)$일 때 $(f(x_1) <= f(x_2)$를 만족하는 함수이며, 그래프는 왼쪽에서 오른쪽으로 갈 때 줄곧 상승하거나 평탄한 구간이 있을 수 있습니다.

## 관련 문제

> 해결한 문제들 :  [기능개발](https://school.programmers.co.kr/learn/courses/30/lessons/42586), [징검다리건너기](https://school.programmers.co.kr/learn/courses/30/lessons/64062)

이 문제들에서 해결해야하는 조건은 명확했습니다. 특정조건을 찾고 해당 조건을 기준을 초과하는 경우 Deque 에 저장된 값을 제거하는 방식으로 진행하는 것입니다.

대표적으로 징검다리 건너기 문제를 예시로 설명을 해보겠습니다. 먼저 이 문제에서 필요한 조건에 대해서 이야기해보겠습니다. 

- 돌다리를 건너는 사람은 반드시 인접한 돌다리 중 건널 수 있는 가장 가까운 돌다리를 건너야만한다.
- 돌다리는 사람들이 지나갈때마다 1 씩 감소하게 되는데 0이 될 경우 해당 돌다리는 점프로 건너 뛰어야 한다.
- 이 문제에 주어진 조건은 $K$ 는 0이된 돌다리를 점프할 수 있는 최대 돌다리의 개수이다.

이러한 조건을 만족시키는 Deque 의 상태를 업데이트하면서 Deque 내의 최댓값 중 최솟값을 찾는 것이 이 문제를 해결할 수 있는 조건이었습니다. 이유는 명확합니다. 점프를 할 수 있는 최대 $K$의 값은 **슬라이딩 윈도우(Window)의 크기**입니다. 

반면 **Deque의 길이**는 윈도우 내에서 단조성(Monotonicity)을 유지하기 위해 값이 계속 제거되므로, 실제로는 $K$보다 훨씬 작거나 같게 유지됩니다. Deque의 길이는 $K$와 일치하지 않으며, 단지 저장된 인덱스들의 차이가 $K$를 넘지 않도록 관리될 뿐입니다.

Deque의 경우 조건을 만족하면서 건널 수 있는 다리들의 사람 수가 저장이 됩니다. 돌다리의 크기가 건널 수 있는 최대 사람의 개수이기 때문입니다.

여기서 주의해야 하는 부분은 JavaScript 의 경우 Deque 의 `shift()` 연산자를 사용해서는 안된다는 것입니다. JS 의 `shift()` 연산자는 배열의 첫번째 요소를 건드리기 때문에 배열 내의 모든 값들이 한 칸씩 앞으로 움직이는 동작을 수행하게 됨으로써 작업시간이 $O(N)$ 이 되기 때문에 적합하지 않습니다.

그렇기 때문에 문제에 주어진 입력 값의 크기를 고려하였을때 너무 큰 크기일 경우에는 `head` 의 인덱스 값을 사용하여 이 값을 배열의 첫번째 인덱스 값이라고 가정하고 문제를 해결해나가는 방법이 필요합니다. 

또한 Deque 에 할당되는 값들은 배열 내의 값들이 아닌 배열의 인덱스들이 할당되어야 합니다. 인덱스를 저장해야 하는 **결정적인 이유는 유효 기간(Window Range) 관리** 때문입니다. 윈도우가 오른쪽으로 이동할 때, 덱의 맨 앞에 있는 원소가 현재 윈도우($i - K + 1$ ~ $i$)를 벗어났는지 확인하려면 해당 원소의 물리적 위치(Index)를 알아야만 $O(1)$로 판별이 가능합니다. 중복 값 처리는 단조성을 유지하는 비교 연산($<$ 또는 $\le$) 과정에서 자연스럽게 해결되는 문제입니다.
