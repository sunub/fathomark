## DP 범위를 좁혀가면서 탐색하는 문제

문제 : [땅따먹기](https://school.programmers.co.kr/learn/courses/30/lessons/12913)

```plaintext
| 1 | 2 | 3 | 5 |
| 5 | 6 | 7 | 8 |
| 4 | 3 | 2 | 1 |
```

위와 같은 구조로 주어지는 데이터에서 하나의 열을 선택하였을 경우 다른 열의 선택에 제한이 발생하는 문제가 있습니다. 위의 문제의 경우 가능한 경우와 가능하지 않은 경우를 분리하여 누적해가면서 계산을 수행해야 합니다.

예를들어, 첫번째 열의 `1`을 선택하였을 경우의 1의 인덱스 이외의 값들에서의 최대 값을 누적해가면 문제의 정의를 어기지 않으면서 모든 경우를 탐색할 수 있습니다. 이전 행과 같은 열을 선택하지 않는다는 보장은 **비교 대상에서 해당 열의 인덱스를 명시적으로 제외하는 방식**으로 이루어집니다.

```js
land[i][0] += Math.max(land[i-1][1], land[i-1][2], land[i-1][3]);
```

1. **상태 정의:** `land[i][0]`은 '현재 행(`i`)의 0번째 열을 밟았을 때까지의 최대 누적 점수'를 의미합니다.
    
2. **조건 적용 (중복 방지):** 현재 행의 0번째 열을 밟기 위해서는 문제의 규칙에 따라 직전 행(`i-1`)에서 0번째 열을 밟지 않았어야 합니다.
    
3. **값 도출:** 따라서 직전 행에서 선택할 수 있었던 유효한 경로는 1번째, 2번째, 3번째 열뿐입니다. 코드는 `Math.max` 함수에 `land[i-1][0]`을 아예 전달하지 않고 `[1]`, `[2]`, `[3]` 값만 전달하여 최댓값을 구합니다.

현재 인덱스를 기준으로 조건을 달성하기 위한 상태의 조건에 맞춰 점화식을 정의해야 한다. 길이가 짧은 배열 부터 문제의 조건을 달성하는 조건에 대해서 생각해보면서 점화식을 고려하는 방법 또한 고려하여야만 한다.

## 냅색 문제

냅색문제는 dp 를 대표하는 문제입니다. 냅색 문제를 해결할때 가장 중요한 것은 기준을 어떠한 것으로 삼을 것인지에 대한 것이 중요합니다. 냅색 문제는 값을 저장할 수 있는 크기에 제한이 존재하기 때문에 제한된 크기 내에 최대 비용, 최대 이익을 얻을 수 있는 경우를 찾아야하기 떄문입니다.

이 문제를 해결하기 위한 핵심 사고 과정은 **DP 테이블의 상태(State)를 정의하고, 현재 물건을 배낭에 넣을지 말지 결정하는 점화식을 세우는 것**입니다.

DP 배열의 행(row, `i`)은 '탐색 중인 물건의 인덱스'를, 열(col, `cw`)은 '현재 허용된 배낭의 임시 용량'을 의미합니다. 즉, `dp[i][cw]`는 '`i`번째 물건까지 고려했고, 배낭의 임시 용량이 `cw`일 때 얻을 수 있는 최대 가치'를 저장합니다.

이 문제에서 세워야하는 조건은 **가방에 수용가능한 최대 무게의 값을 DP 에 저장하는 것** 이었습니다. 이 조건을 달성하기 위해서는 무게가 가벼운 것부터 배열에 저장해야 합니다. 이러한 이유는 무게가 작은 것을 담아야 가방에 공간이 많이 남아 값을 누적해가면서 최대의 가치를 구할 수 있기 때문입니다.

```js
  for (let i = 1; i < N; i++) {
    const [w, v] = nums[i];
    for (let cw = 1; cw <= K; cw++) {
      if (cw < w) {
        dp[i][cw] = dp[i - 1][cw];
        continue;
      }

      dp[i][cw] = Math.max(
        dp[i - 1][cw],
        (cw - w >= 0 ? dp[i - 1][cw - w] : 0) + v,
      );
    }
  }
```

가로열을 1부터 수용 가능한 배낭의 최대 크기인 K까지 반복하여 탐색하는 이유는, 작은 배낭 용량(하위 문제)에 대한 최적해를 먼저 구하고 이를 누적하여 최종적으로 용량이 K일 때(상위 문제)의 최적해를 도출하기 위함(Bottom-Up)입니다. 하위 문제의 결과가 상위 문제를 계산하는 데 재사용되기 때문에, 용량을 1씩 증가시키며 모든 가능한 배낭 크기에 대한 최적의 가치를 기록해 나가야 합니다.

1. **상태의 이분화 (Include or Exclude):** 질문에서 언급한 바와 같이, 특정 요소를 '선택한다(포함)'와 '선택하지 않는다(미포함)'의 두 가지 상태로만 나누어 결과를 정의할 수 있어야 합니다.
2. **제한된 자원 (Capacity Limit):** 배낭의 최대 무게, 허용된 예산, 피로도 등 소모되는 자원의 총량에 명확한 제한이 있어야 합니다. 이 제한된 자원이 DP 배열의 차원(상태)을 구성하게 됩니다.
3. **최적 부분 구조 (Optimal Substructure):** '최적의 경우를 저장하고 이를 누적해 간다'는 설명에 해당합니다. 하위 단계(이전 인덱스, 더 작은 자원 크기)에서 계산된 최적의 결과값이 상위 단계를 계산할 때 변형 없이 유효하게 사용될 수 있어야 합니다.

문제 : [피로도](https://school.programmers.co.kr/learn/courses/30/lessons/87946)

이 피로도 문제를 기존의 냅색 문제에서 접근했던 방식과 같이 해결하고자 했지만 제대로 해결하지 못했습니다. 이 문제의 배열의 조건을 특정 조건으로 정렬한 후 해결해야 했습니다.

```js
dungeons.sort((a, b) => {
    const l1 = Math.abs(a[0] - a[1]);
    const l2 = Math.abs(b[0] - b[1]);
    if(l1 === l2) {
        return b[0] - a[0];
    }
    return l2 - l1;
});
```

이는 일반적인 냅색과는 차별된다고 이야기한 이유입니다. 일반적인 냅색 문제의 경우 문제의 조건으로 주어지는 값들의 졍렬과는 전혀 상관 없이 정답을 구할 수 있습니다. 왜냐하면 DP 에는 현재의 상태를 포함하지 않았을 경우와 포함하였을 경우 가방에 담을 수 있는 최대 크기를 의미하기 때문입니다.

하지만 이 문제에서는 어떠한 던전을 먼저 탐색할 것인지에 대한 순서가 정답을 결정하는 중요한 조건입니다. 그렇기 때문에 냅색 문제로는 적용할 수 없는게 일반적입니다. 하지만 문제의 조건을 문제의 기준에 맞춰 정렬한 후 하위 단계(이전 인덱스, 더 작은 자원 크기)에서 계산된 최적의 결과값이 상위 단계를 계산할 때 변형 없이 유효하게 사용될 수 있을 경우에는 냅색 문제로 해결을 할 수 있습니다.

이 문제는 "첫 번째 → 세 번째 → 두 번째" 와 같이 이전에 탐색한 던전이 다음 던전에 영향을 주기 때문에 앞서 하위 단계가 최적의 결과값에 유효하게 사용이 되는 경우라고 이야기할 수 있습니다. 

### 1. 1차원 DP 배열과 갱신 방향의 관계

일반적으로 0-1 냅색 문제를 2차원 배열 `dp[i][w]` (i번째 물건까지, 용량 w)로 풀면 이전 단계(`i-1`)의 값을 참조하므로 하나의 물건을 중복해서 사용할 위험이 없습니다. 하지만 이를 공간 최적화하여 1차원 배열 `dp[w]`로 줄일 경우 갱신 방향에 따라 치명적인 차이가 발생합니다.

- **정방향 탐색 (무한 냅색):** 앞에서부터 뒤로(1부터 K까지) 배열을 갱신하면, 방금 현재 물건을 반영하여 갱신된 앞쪽의 `dp` 값을 뒷부분 갱신에 다시 사용하게 됩니다. 이는 "한 물건을 여러 번 넣을 수 있다"는 무한 냅색의 논리가 되어버립니다.
    
- **역방향 탐색 (0-1 냅색):** 뒤에서부터 앞으로(K부터 1까지) 배열을 갱신하면, 갱신에 사용되는 이전 값들은 항상 '현재 물건을 아직 고려하지 않은 이전 단계(`i-1`)의 값'임이 보장됩니다. 따라서 "물건은 단 한 번만 쓸 수 있다"는 0-1 냅색의 논리가 유지됩니다.

### 2. 피로도 코드에서의 적용

작성하셨던 피로도 코드의 핵심 로직을 다시 보겠습니다.

```js
for (let i = 0; i < N; i++) {
    const [needed, cost] = dungeons[i];
    // 역방향 탐색: j가 큰 값에서 작은 값으로 감소
    for (let j = i + 1; j > 0; j--) {
        if (dp[j - 1] >= needed) {
            dp[j] = Math.max(dp[j], dp[j - 1] - cost);
        }
    }
}
```

여기서 `j`는 '탐험한 던전의 수'입니다. 만약 내부 반복문을 역방향(`j--`)이 아닌 정방향(`j++`)으로 순회했다고 가정해 보겠습니다.

1. `j = 1`일 때: `dp[1] = Math.max(dp[1], dp[0] - cost);` (현재 던전을 1번 방문 처리)
2. `j = 2`일 때: `dp[2] = Math.max(dp[2], dp[1] - cost);` (방금 갱신된 `dp[1]`을 바탕으로 현재 던전을 **또** 방문 처리)

결과적으로 하나의 던전을 무한히 반복해서 도는 **무한 냅색 문제**로 변질되며, 게임의 규칙(던전은 한 번씩만 방문 가능)을 위반하게 됩니다.
